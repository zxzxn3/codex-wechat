# 本轮重构结果

2026-11-02。Linux与Windows侧的能力统一到cfg管理的源码；GitHub项目库为临时导出发布目标，
不在项目目录长期维护另一份.git。原始Windows开发源码留存归档分支，临时机器修复脚本不进入活动实现。

## 改动

- 共用连接意图、原生可执行发现和后台准备；App/CLI使用同一接入控制器，代理配置留在外部启动器。
- 微信认证失效、暂停、通知和relink使用共同业务；换身份隔离旧交付，保留Agent选择与用户偏好。
- 子进程取消、超时和管道回收统一；原子JSON临时文件成功/失败均清理。
- 安装依赖集中维护，原生二维码优先，Python回退按需安装；网络installer保持单文件可自举。
- 保留旧紧凑提示、智能切片、附件、queue/steer、中途回复、审批/提问及恢复边界。

源码总量约8400行，比Linux基线增加约800行，未以行数减少作为收益。减少的是分叉维护、
重复责任和临时入口；代价与可取消能力见COMPLEXITY，能力对照见CAPABILITIES。

## 验证

指定测试者对0cb6656固定副本验收，发现并在副本修复旧context未隔离、取消后communicate
永久等待两项缺陷。修正过时夹具并加入独立回归后：301项，296通过、5跳过。生产修复
原样合入6c01c27，文件哈希与被测副本一致。能力审查未发现确定遗漏，不等于保证没有遗漏。

之后发现单文件installer顶层导入新增模块会破坏网络自举；5700922撤销多余拆分。
指定测试者对5d3d6e6复验：安装相关65项，63通过、2跳过；相关21项通过；额外19项检查通过。
实际复制单文件运行help/dry-run，并进行离线干净release构建、模块编译、入口和current检查。

本轮未做Windows 5.1/Task Scheduler/Job Object/App实机、真实微信/CDN/扫码、三端并发、
原生请求路由、DeepSeek密钥环、真实systemd或公网安装验证。不能由离线通过推导这些组合可用。
本机Linux代理启动器另移除了后台核对，只保留原有代理设置与exec转交；该删除仅静态审阅。
