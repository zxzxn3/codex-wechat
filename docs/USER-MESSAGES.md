# 用户提示设计

本文约束微信用户可见的成功回执、失败提示和生命周期通知。提示模板仍以
`codex_wechat/prompts.py` 为唯一默认来源；`config.prompts` 只能覆盖这些名字，
详见 [CONFIGURATION](CONFIGURATION.md)。内部状态机见 [DELIVERY](DELIVERY.md)，
会话与 writer 所有权见 [ARCHITECTURE](ARCHITECTURE.md)。

## 原则

1. **结果优先**：先回答用户要求的结果，例如“已切换会话”“正在停止”“已排队”，
   不叙述桥如何完成。
2. **机制后置**：队列、worker、detach、writer、重连、恢复和持久化属于开发文档，
   不进入成功回执。
3. **隐式行为不播报**：显式命令必然带来的清理动作不重复说明。例如 `/new`、`/switch`
   丢弃旧来源的未交付输入和输出，只在 [DELIVERY](DELIVERY.md) 说明。
4. **安全边界仍要提示**：可能重复执行、静默丢失、旧连接未清理、能力回落或需要用户在
   桌面处理的风险，必须保留结果层面的警告，不能为了简洁而隐藏。
5. **失败要可行动**：失败提示给出下一步，如重新选择、等待、查看 `/status`、改用桌面端；
   不要求用户理解内部 RPC 或状态名。
6. **显示当前值，不复述变化过程**：设置成功显示生效后的模型、强度或目录，不描述旧值和
   迁移步骤。
7. **生命周期通知优先**：能用开始/结束事件表达的过程，不再额外发送“请求已提交”回执。
   例如上下文压缩由 `COMPACT_STARTED`、`COMPACT_FINISHED` 和中断提示表达。

## 显示与不显示

| 应当显示 | 不应进入用户提示 |
| --- | --- |
| 命令结果与当前选择 | 请求已入队、worker 已接单、控制 ID、保存顺序 |
| 需要用户选择的候选 | `detach`、`thread/unsubscribe`、`thread/delete`、writer 状态 |
| 可执行的失败原因和下一步 | 重连、恢复、重放和额度的内部实现 |
| 不明显的不可逆后果 | 显式命令必然发生的清理细节 |
| 投递未知、重复执行和旧连接风险 | 成功路径上的持久化与队列机制 |
| 当前生效的设置值 | 设置从哪个回合开始生效的内部边界 |

判断标准：如果隐藏后用户可能误以为任务没执行、重复提交、丢失结果或无法恢复，就保留
结果层面的警告；否则只写用户做了什么、现在是什么、下一步是什么。

## 已采用的取舍

- `/new`、`/switch` 只显示“已新建会话”或“已切换会话”及当前会话摘要，不重复播报旧回合
  detach 和旧输入输出作废。
- `/compact` 不发送“已请求压缩”的同步回执，由压缩生命周期通知报告开始、结束或中断。
- `/get` 显示“正在发送附件…”，不暴露附件进入内部发送队列。
- `/stop` 显示“正在停止。”；只有实际清空排队消息时才附加数量。
- 排队确认附“用 `/u` 撤回”，让用户不必另外查短命令。
- `/settings shared` 在桌面仍占用会话时只提示这一结果，不解释下一条消息如何自动接管。
- 后端连接失败只说明失败和正在重连，不额外解释待办保留策略。
- 会话被其他客户端占用时说明需要等待或先在桌面释放，不解释 writer 队列和超时状态。
- 命令参数形态不明显时，错误提示附一行 `例：...`；正常成功回执和普通列表不加示例，避免占用屏幕。

## 只写在开发文档的隐式约定

- `/new`、`/switch` 的旧回合后台继续、旧来源输出/当前输入/排队输入作废、worker 合成
  discarded 结果，以及目标准备失败时保留旧状态。
- 目标 thread 的 prepare/commit 顺序、`thread/delete` 与 `thread/unsubscribe` 的使用边界。
- App follower、writer 所有权、共享后台回落和旧连接释放。
- 压缩请求与实际开始、完成、中断之间的状态区别。
- 输入提交的 accepted、uncertain、不自动重放，以及不承诺跨进程恰好一次执行。
- 控制队列上限、lane、outbox、发送预算、附件排队和投递确认机制。
- `/model`、`/effort`、`/cwd` 只修改后续回合，以及当前回合和已在途输出的隔离规则。

这些约定应写入 [DELIVERY](DELIVERY.md)、[ARCHITECTURE](ARCHITECTURE.md)、
[CONFIGURATION](CONFIGURATION.md) 或对应的决策记录，而不是复制进用户回执。
